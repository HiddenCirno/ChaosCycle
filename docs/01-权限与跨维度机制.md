# 1.20.1 Forge：权限树与跨维度传送速查

> 基于 Forge 47.x 的 mapped jar（Parchment 2023.07.16-1.20.1）与 47.4.23 patches 实测。

## 一、权限

### 1. 原版等级

`MinecraftServer#getProfilePermissions(GameProfile)`：

```text
if (!isOp(profile)) return 0;
entry = ops.get(profile);
if (entry != null) return entry.level;          // ops.json 1–4
if (isSingleplayerOwner(profile)) return 4;
if (isSingleplayer()) return allowCheatsForAllPlayers ? 4 : 0;
return getOperatorUserPermissionLevel();        // server.properties op-permission-level，默认 4
```

- `Entity#getPermissionLevel()` 默认 0；`ServerPlayer` 覆盖为 `getProfilePermissions`。
- `Entity#hasPermissions(n)` / `CommandSourceStack#hasPermission(n)` = `level >= n`。
- `Entity#createCommandSourceStack()` 用 `getPermissionLevel()`；控制台固定 4。
- `CommandSourceStack#withPermission(n)` 精确改写；`withMaximumPermission(n)` 压到不超过 n。
- `/function` 用 `withMaximumPermission(2)`；`ServerFunctionManager#getGameLoopSender()` 是 2 级源。
  命令块/函数里的命令最多按 2 级执行。

### 2. 命令树

- `CommandDispatcher<CommandSourceStack>` 是一棵树，每个节点可带 `requires`。
- `Commands#sendCommands(player)` 通过 `CommandHelper.mergeCommandNode` 只把 `canUse(player.createCommandSourceStack())` 的节点发给客户端。
- 服务端 `Commands#performCommand` 仍用完整 dispatcher 执行，Brigadier 会再次检查 `canUse`。
- 常见等级：`/give` `/tp` `/setblock` `/gamemode` `/execute` `/reload` = 2；`/op` `/ban` `/kick` `/whitelist` = 3；`/stop` `/save-all` = 4。

### 3. 生存/冒险/创造/旁观

`GameType#updatePlayerAbilities`：

| 模式 | mayfly | instabuild | invulnerable | flying | mayBuild |
|---|---|---|---|---|---|
| SURVIVAL | false | false | false | false | true |
| CREATIVE | true | true | true | 保持 | true |
| ADVENTURE | false | false | false | false | false |
| SPECTATOR | true | false | true | true | false |

- `Player#mayBuild()` = `abilities.mayBuild`。
- `Player#canUseGameMasterBlocks()` = `instabuild && permissionLevel >= 2`。
- `Player#blockActionRestricted`：冒险/旁观限制破坏；冒险需要 `can_break`。
- `ItemStack#onItemUse`：`mayBuild=false` 时，放置需要 `can_place_on`。
- `ServerLevel#mayInteract` → 出生点保护/世界边界；`DedicatedServer#isUnderSpawnProtection` 对 op 直接返回 false。
- `ServerPlayerGameMode#destroyBlock`：`GameMasterBlock` 且 `!canUseGameMasterBlocks()` 时拒绝。
- 命令方块/结构方块/拼图方块的数据包处理要求 `canUseGameMasterBlocks()`。

### 4. Forge PermissionAPI

- `PermissionAPI.getPermission(ServerPlayer, PermissionNode<T>, contexts...)`
- `PermissionNode<T>`：节点名、`PermissionType<T>`、默认 `PermissionResolver<T>`、动态上下文。
- `DefaultPermissionHandler` 只调用 `node.getDefaultResolver().resolve(...)`。
- `PermissionGatherEvent.Nodes` 注册节点；`PermissionGatherEvent.Handler` 替换 handler。
- 节点名只是命名层级，**默认 handler 不自动继承**；继承要自己实现。
- `PermissionsChangedEvent`（复数）在权限等级变化时触发。

## 二、跨维度传送

### 三条路径

| 路径 | 入口 | 玩家对象 | `EntityTravelToDimensionEvent` |
|---|---|---|---|
| 传送门 | `NetherPortalBlock` / `EndPortalBlock` → `changeDimension` | 保留 | ✅ |
| 命令/直接 | `ServerPlayer#teleportTo(ServerLevel, ...)` / `Entity#teleportTo(ServerLevel, ...)` | 玩家保留；普通实体新建 | 玩家 ✅；普通实体 ❌ |
| 重生 | `PlayerList#respawn` | 新建 `ServerPlayer` | ❌（触发 `PlayerEvent.Clone`） |

### 玩家命令传送

```text
ServerPlayer.teleportTo(dest, x, y, z, yaw, pitch):
  同维度 -> connection.teleport(...)
  跨维度:
    onTravelToDimension 事件
    ClientboundRespawnPacket(KEEP_ALL_DATA=3)
    removePlayerImmediately(CHANGED_DIMENSION); revive()
    moveTo; setServerLevel; dest.addDuringCommandTeleport
    triggerDimensionChangeTriggers
    connection.teleport; gameMode.setLevel
    sendLevelInfo / sendAllPlayerInfo
    PlayerChangedDimensionEvent
```

### 玩家传送门

```text
ServerPlayer.changeDimension(dest, teleporter):
  onTravelToDimension 事件
  末地 -> 主世界 + 原版 PortalForcer -> WIN_GAME / 制作人员名单分支
  否则:
    ClientboundRespawnPacket(KEEP_ALL_DATA=3)
    removePlayerImmediately; revive()
    info = teleporter.getPortalInfo(this, dest, this::findDimensionEntryPoint)
    teleporter.placeEntity(...)  // 必须返回同一个玩家
    placeEntity 内部: setServerLevel; connection.teleport; addDuringPortalTeleport; triggerDimensionChangeTriggers
    发能力/药水/音效; PlayerChangedDimensionEvent
```

- `Entity#findDimensionEntryPoint`：
  - 末地：`END_SPAWN_POINT` / 高度图出生点；主世界→末地时 Y-1、朝向 90/0，并创建黑曜石平台。
  - 下界↔主世界：`DimensionType.getTeleportationScale`（8×）；世界边界夹取；`getExitPortal`。
- `PortalForcer#findPortalAround`：POI 搜索半径 16（目标下界）/128（目标主世界）；`PoiManager.ensureLoadedAndValid`。
- `ServerPlayer#getExitPortal` 找不到门时会 `createPortal`；普通实体不会自动建门。
- 末地门：`EndPortalBlock#entityInside`，目标 = 当前 END ? OVERWORLD : END。

### 普通实体

```text
Entity.changeDimension(dest, teleporter):
  onTravelToDimension 事件
  unRide
  getPortalInfo / placeEntity
  removeAfterChangingDimensions (CHANGED_DIMENSION)
  resetEmptyTime
  return newEntity
```

- 默认 `ITeleporter#placeEntity` 调 `repositionEntity.apply(true)`；普通实体的 lambda 用 `EntityType.create(dest)` + `restoreFrom` 新建实体。
- `Entity#teleportTo(ServerLevel, ..., Set, ...)` 跨维度也会新建实体，但**不触发** `EntityTravelToDimensionEvent`。

### 客户端同步

- `ServerGamePacketListenerImpl#teleport`：`awaitingPositionFromClient`、传送 id、`ClientboundPlayerPositionPacket`、等待 `ServerboundAcceptTeleportationPacket`、`resetPosition`。
- `ClientboundRespawnPacket`（`KEEP_ALL_DATA=3`）、`ClientboundPlayerAbilitiesPacket`、`ClientboundChangeDifficultyPacket`、`ClientboundUpdateMobEffectPacket`、`ClientboundLevelEventPacket(1032)`、`ClientboundGameEventPacket.WIN_GAME`。
- `ServerLevel#addDuringTeleport` → `addEntity`；`addDuringCommandTeleport`/`addDuringPortalTeleport`/`addRespawnedPlayer` → `addPlayer`。
- `ServerPlayer#teleportTo(..., Set, ...)` 加 `TicketType.POST_TELEPORT`。

### Forge 事件

- `EntityTravelToDimensionEvent`（可取消；传送门/玩家直接传送会触发；普通实体 `Entity.teleportTo` 不触发；`PlayerList.respawn` 不触发）。
- `PlayerChangedDimensionEvent`（到达后）。
- `PlayerEvent.Clone`（`restoreFrom`，`isWasDeath()`）。
- `PlayerEvent.PlayerRespawnEvent`。
- `EntityJoinLevelEvent` / `EntityLeaveLevelEvent`。
- `PlayerEvent.PlayerChangeGameModeEvent`。
- `PermissionsChangedEvent`。

## 三、ChaosCycle 采用的设计

### 命令执行器

- 两个按钮对应 `GameType.SURVIVAL / CREATIVE`。
- 点击后客户端发 `C2SSetGameMode`；服务端调用 `player.setGameMode(gameType)`，并通过
  `S2CExecutorState` 回传当前模式。
- ⚠️ **必须用 `ServerPlayer#setGameMode`**。`ServerPlayerGameMode#changeGameModeForPlayer` 只改服务端字段、
  广播 `ClientboundPlayerInfoUpdatePacket`，**不发 `ClientboundGameEventPacket.CHANGE_GAME_MODE`**；
  客户端因此不知道模式变了（旁观仍显示物品栏、生存能开创造背包）。`setGameMode` 还会触发
  `ForgeHooks.onChangeGameType`、能力同步、旁观摄像机处理。
- 执行指令时固定使用：

  ```java
  player.createCommandSourceStack().withPermission(2)
  ```

  - 权限 0 的玩家也能执行 2 级指令；
  - **最高只有 2 级**，无法通过本道具执行 `/op`、`/stop` 等 3/4 级命令。
- 去掉前导 `/`；长度 ≤256；`Commands#performPrefixedCommand`。
- 界面底部是聊天栏式输入：`EditBox` 只作为文本/光标模型（`setBordered(false)`），
  不注册为渲染控件，但通过 `screen.setFocused(commandField)` 成为焦点，
  这样 `CommandSuggestions` 的 Tab 判定（`screen.getFocused() == input`）成立。
- 输入语义与原版聊天栏一致：**普通文本走 `ClientPacketListener#sendChat` 作为聊天发送；
  以 `/` 开头才走本模组的 2 级权限指令包**。`commandsOnly=false`，所以补全只在有 `/` 时触发。
- 直接复用原版 `CommandSuggestions`：高亮、Tab、↑/↓ 循环、鼠标悬停选择与虚线框、
  使用提示、`keepSuggestions` 等全部是原版行为。
- 窗口缩放会走 `resize → repositionElements → rebuildWidgets → init`，同一个 Screen 实例
  会被重新初始化。init 开头快照输入值/光标/输出区行/历史游标，重建控件后恢复；
  `realHeight` 取窗口的 `GuiScaledHeight`，避免读到上一次布局写入的补全用假高度。
- ⚠️ `CommandSuggestions` 的 Y 坐标是给原版聊天栏写死的
  （`anchorToBottom ? screen.height - 12 : 72`）。对策：布局完成后把 `Screen.height`
  改成 `top + INPUT_BOX_Y + 15`，使列表底边落在输入行上方；`renderBackground` 里
  临时恢复 `realHeight` 再调用 `super`。
- 选择器参数（`@e[...]`）由客户端本地计算，先经过
  `EntityArgument.listSuggestions → ForgeHooks.canUseEntitySelectors(source)`
  的 2 级权限检查。界面打开期间把 `ClientPacketListener` 里唯一的
  `ClientSuggestionProvider` 字段（按类型反射查找）替换成
  `FixedPermissionSuggestionProvider`，只把 `hasPermission(<=2)` 放宽为 true；
  关闭界面时换回原实例。
  - 不修改 `LocalPlayer` 权限等级；只影响补全，不影响服务端校验。
  - 子类不覆写 `customSuggestion`：ASK_SERVER 的响应会回到连接字段当前持有的实例，
    委托给原实例会让 future 挂死。
- 历史消息调用原版 `ChatComponent#getRecentChat()` / `addRecentChat()`，
  `moveInHistory` 语义与 `ChatScreen` 相同；执行后清空输入并重置历史游标。
- 非系统聊天（`ClientChatReceivedEvent#isSystem() == false`，玩家发言、`/say` 等）
  实时追加到输出区；系统消息跳过，因为指令反馈已经由 `S2CCommandOutput` 回传，避免重复。
- 补全命令树必须与执行权限一致（2 级），否则权限 0 玩家的客户端树里根本没有 `/give`、`/tp`：
  - 打开界面：`C2SCommandTreeRequest(elevated=true)` → 服务端用
    `player.createCommandSourceStack().withPermission(2)` 重新过滤命令树并下发
    `ClientboundCommandsPacket`；
  - 关闭界面：`elevated=false` → `Commands#sendCommands(player)` 恢复玩家原本的树。
  - 过滤逻辑复用服务端私有的 `Commands#fillUsableCommands`，通过**参数类型形状**反射查找，
    不依赖方法名，生产环境重混淆后仍然有效。
- 服务端校验手持物品；客户端只负责发送。
- 输出区：执行时用一个自定义 `CommandSource` 替换 source，把 `sendSystemMessage`
  收到的文本（`sendSuccess` / `sendFailure` 的最终出口）抄一份，连同 `S2CCommandOutput`
  发回客户端，追加到聊天栏式输出区；同时照常转发给玩家聊天栏。
  - `shouldInformAdmins()` 返回 false：source 不是玩家对象，否则 `broadcastToAdmins`
    的 `p != source` 判断会让执行者本人再收到一份重复的 admin 格式消息。

### 超空间定位器

- 数据存放在**玩家自身**的 `getPersistentData()`（`ForgeData/ChaosCycleWaypoints`），
  不写物品 NBT；同一玩家的所有定位器共享，换道具/死亡不丢。
- 每条 = 名称（可空）+ 维度 + XYZ + Yaw/Pitch；最多 32 条。
- 名称为空时列表按 `#n 维度 @ x, y, z` 显示，有名字时显示 `#n 名字 · 维度`。
- 名称长度上限 32，服务端 `strip` + 截断；客户端只负责提交。
- GUI：左侧坐标列表 + 名称/XYZ 输入框，按钮为
  **保存当前坐标 / 取当前坐标 / 保存修改 / 删除 / 传送**。
- **不提供维度编辑**：条目维度在“保存当前坐标”时确定，之后只改 XYZ
  （避免误把坐标存进错误维度；需要换维度就重新保存一条）。
- 服务端在**添加、修改、传送**三处都重新校验：
  - 条目维度：`ResourceLocation.tryParse` + `server.getLevel(ResourceKey.create(Registries.DIMENSION, id))`
  - 坐标有限
  - `minBuildHeight <= Y < maxBuildHeight`
  - `worldBorder.isWithinBounds`
- 修改时维度取自**服务端已存条目**，不再接受客户端传入的维度字符串。
- 传送用 `ServerPlayer#teleportTo(dest, x, y, z, Set.of(), yaw, pitch)`（保留玩家对象，触发事件，发位置包）。
- 跨维度传送是 `ClientboundRespawnPacket(KEEP_ALL_DATA)` + 位置包，客户端可能清掉飞行；
  传送前记录 `abilities.flying`，传送后补回并 `onUpdateAbilities()` 重新同步。
- 维度被移除/坐标越界时拒绝并提示，不产生空指针。
- **传送不需要权限**；添加/修改/删除只要求手持道具。
